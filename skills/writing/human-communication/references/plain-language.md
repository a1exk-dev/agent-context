# Plain-language rules

These rules come from ISO 24495-1:2023, *Plain language — Part 1: Governing principles and guidelines*. The ISO page for the standard is https://www.iso.org/standard/78907.html. The rules are our own words for its 4 principles. This file holds no text of the standard.

## When you select what to write

These rules make the text relevant: the reader gets what the reader needs.

- Give the result first. Then give the details.
- Keep only the details on the topic of the request. Remove the steps that you did and the facts that the reader does not need.
- Do not add a side note that the request did not ask for. For example, do not report a style problem in a comment when the request asks what the code does.
- "Short" has no word limit. A text is short when it gives the result first and keeps only the details on the topic.
- Give the next step when one exists, for example the command that the reader runs or the decision that the reader makes.

## When you put the text in order

These rules make the text findable: the reader finds the parts that the reader needs.

- In a document for persons, use a title, headings, lists, and tables. Give each heading the subject of its section.
- Put the sections and the steps in the sequence of the tasks of the reader.
- Keep background information separate from the steps.

## When you select the words and the sentences

These rules make the text understandable: the reader understands it on the first read.

- Obey the rules in `ste-rules.md` in this folder.
- Use a neutral and direct tone.
- Make all parts of the text agree.

## When the reader uses the text

These rules make the text usable: the reader can act on it.

- Show an example when words alone are not clear. `SKILL.md` in the folder above this file gives the cases that need a diff, a code block, or a before and after.
- Give each command, path, and name in the exact form that the reader types or opens.
